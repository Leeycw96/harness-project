接口设计样例

现行 Spec 的接口展示样例：HTTP 差异、HTTP 回调与 RPC。请标注希望调整的结构和信息量。

接口设计

POST /orders/{id}/cancel

入参沿用：路径 id（String，必填），请求头 Idempotency-Key（String，必填）。无请求体。

出参：202（仅列变更字段）。

字段类型必填说明
statusString是修改：新增枚举 REFUND_PENDING，表示退款处理中
refundRequestIdString是新增：退款请求 ID

响应 JSON（局部，仅变更字段）：

{
  "status": "REFUND_PENDING",
  "refundRequestId": "refund-123"
}

POST /refunds/callback

入参（请求体，仅列本次契约）：

字段类型必填说明
requestIdString是退款请求 ID
resultString是SUCCESS：退款成功；FAILED：退款失败
signatureString是渠道签名，沿用既有签名算法

请求 JSON（局部）：

{
  "requestId": "refund-123",
  "result": "SUCCESS",
  "signature": "example-signature"
}

出参：200，无响应体。

RPC InventoryService.reserve(ReserveRequest)

入参（仅列本次契约）：

字段类型必填说明
requestIdstring是预占请求 ID；同一请求重复调用返回原结果
skuIdstring是商品规格 ID
quantityint32是预占数量，必须大于 0

出参：ReserveReply（仅列本次契约）。

字段类型必填说明
reservationIdstring是库存预占编号
expiresAtint64是预占到期时间，Unix 毫秒时间戳
版式样例，接口、字段与错误均需按实际项目核实。
