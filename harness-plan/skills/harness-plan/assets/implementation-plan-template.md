# <Action-oriented change title>

## Purpose

说明用户在改造后可以完成什么、为什么需要本次改造，以及如何观察到结果。

## Current Flow

按顺序描述当前入口、关键判断、状态变化、外部调用、副作用和终态。列出作为依据的 CallChain、代码、配置或测试路径；没有现有能力时明确说明。

## Target Flow

按顺序描述改造后的主流程、异常分支、状态变化、副作用和终态。每一步关联对应 feature slug。

## Change Map

按 feature slug 分节。列出仓库相对路径、已有模块及公共类或接口、当前职责和目标职责；新文件必须说明创建位置和用途。不规定私有辅助方法或方法体。

## Interfaces and Data

描述 API、RPC、消息、事件、表结构、状态字段及兼容或迁移要求。没有变化时说明为什么无需修改。

## Technical Decisions

逐项记录决策驱动因素、项目既有惯例或候选方案、用户确认的选择、理由、正负影响和官方或一手来源。没有新选型时记录沿用的项目惯例及证据路径。

## Cross-cutting Constraints

只记录本需求涉及的事务边界、一致性、幂等、并发、权限、安全、性能和错误处理要求。无相关要求时明确说明。

## Implementation Sequence

按依赖顺序拆分可独立验证的批次。每个批次写明覆盖的 feature、修改目标、前置条件和完成证据。

## Validation

列出准确的工作目录、命令、业务场景、输入和预期输出。覆盖正常路径、关键异常和重要副作用。

## Risks and Recovery

说明实现、迁移和运行风险，以及安全重试、回滚或恢复方法。没有特殊风险时说明依据。
