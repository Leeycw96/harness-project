库存预占服务

从用户诉求、本次目标流程与功能设计评估方案。审阅后在会话中提出修改或确认。

背景

  • User Story：作为下单方，我希望先预留足够的库存，以便多个订单同时申请时不会超卖。
  • User Story：作为下单方，我希望成交时扣减库存、放弃时释放库存，以便库存反映订单的实际结果。

功能目标

reserve-stock — 创建预占

  • 目标：按订单预留商品库存，并让查询显示账面库存、预占量和可用量。

验收标准：

  • 正整数数量小于或等于可用库存时创建成功；恰好用尽可用库存也允许。
  • 同一订单重复相同申请返回同一预占，不重复占用；换商品或数量时拒绝。
  • 已确认或已取消的订单重复申请不会重新预占。
  • 商品不存在、数量无效或库存不足时拒绝，库存保持不变。
  • 多个订单同时申请不会超卖，服务重启后仍能查询保存的库存和预占结果。
  • 查询同时显示账面库存、仍被占用的数量和剩余可用数量。

confirm-reservation — 确认扣减

  • 目标：将有效预占确认为成交，并且只扣减一次账面库存。

验收标准：

  • 首次确认有效预占后，账面库存和预占量减少相同数量，可用量保持不变。
  • 重复确认返回已确认结果，不再次扣减。
  • 已取消或不存在的预占不能确认，库存保持不变。
  • 同一预占同时收到确认和取消时，只能成功进入其中一种终态。

cancel-reservation — 取消释放

  • 目标：取消有效预占，恢复可用库存，并且只释放一次。

验收标准：

  • 首次取消有效预占后，账面库存不变，预占量减少，可用量恢复相同数量。
  • 重复取消返回已取消结果，不再次释放。
  • 已确认或不存在的预占不能取消，库存保持不变。
  • 取消后重复创建同一订单不会重新占用库存。

数据模型设计

CREATE TABLE IF NOT EXISTS reservations (
    order_id TEXT PRIMARY KEY NOT NULL,
    sku TEXT NOT NULL REFERENCES products(sku),
    quantity INTEGER NOT NULL CHECK (typeof(quantity) = 'integer' AND quantity > 0),
    status TEXT NOT NULL CHECK (status IN ('RESERVED', 'CONFIRMED', 'CANCELLED'))
);
CREATE INDEX IF NOT EXISTS idx_reservations_sku_status ON reservations(sku, status);

初始化在现有迁移后执行新增迁移，保留原商品数据；新表初始为空。回退应用时先停用预占写入口并处理有效预占，保留新表和已写数据。

接口设计

POST /reservations

请求体必须是 JSON 对象；标识按原字符串匹配，不自动去空格或改大小写。

字段类型必填说明
order_idString是非空白订单标识，同时作为唯一预占标识
skuString是非空白商品标识
quantityInteger是1 至 9223372036854775807；拒绝布尔值、小数和数字字符串

成功均返回 200，下表是三个写接口共用的完整预占响应。

字段类型必填说明
order_idString是原订单标识
skuString是原商品标识
quantityInteger是原预占数量
statusString是当前状态：RESERVED、CONFIRMED 或 CANCELLED

响应 JSON 示例：

{"order_id":"order-001","sku":"DEMO","quantity":2,"status":"RESERVED"}

同一订单、商品和数量重试返回同一记录及当前状态，终态记录也保留；不重新激活。商品或数量不同始终返回冲突，先于商品存在性和剩余库存判断。

三个写接口共用错误响应 {"error":"原因"}。格式错误、缺字段或类型/范围错误返回 400；未知商品返回 404；订单冲突或库存不足返回 409。写锁等待超时返回 503，其他数据库异常返回 500；失败不改变库存。

GET /inventory/{sku}

沿用现有商品查询和未知商品的 404；无请求体。成功仍返回 200，保留原字段，仅新增：

字段类型必填说明
reservedInteger是仅 RESERVED 记录的数量之和；没有记录时为 0
availableInteger是stock 减 reserved

响应 JSON（新增字段局部示例）：

{"reserved":2,"available":8}

POST /reservations/{order_id}/confirm

字段类型必填说明
order_id（路径）String是原订单标识，作为一个 URL 编码的路径段

无请求体。成功返回 200 和共享预占响应，status 为 CONFIRMED；重复确认相同。未知预占返回 404，已取消或库存数据不一致返回 409；错误体及数据库异常沿用共享契约。

POST /reservations/{order_id}/cancel

字段类型必填说明
order_id（路径）String是原订单标识，作为一个 URL 编码的路径段

无请求体。成功返回 200 和共享预占响应，status 为 CANCELLED；重复取消相同。未知预占返回 404，已确认返回 409；错误体及数据库异常沿用共享契约。
