# BUG-001 — 折扣金额多保留了一位小数

## 问题与根因

- 当前现象：输入金额 10.05、折扣 0.9 时返回 9.045，未按约定保留两位小数。
- 预期行为：返回 9.05，沿用现有金额计算约定。
- 预期依据：项目已确认的金额舍入规则；此文档为示例，使用时替换为实际要求与证据。
- 定位结论：已定位
- 根因：折扣分支直接返回乘法结果，遗漏现有金额格式化函数。
- 证据：核对 `src/pricing.py::discount` 与已有舍入测试；示例路径须替换为真实代码位置。
- 事项分类：缺陷
- 处理路径：fix
- 分流依据：只修复现有计算逻辑，业务规则、状态、接口和数据模型均不变。

## 修复方案

- 修复目标：折扣金额按已有规则保留两位小数。
- 代码改造点：`src/pricing.py::discount` — 复用现有金额格式化函数处理折扣结果。
- 代码改造点：`tests/test_pricing.py` — 补充小数舍入及现有整数金额的回归测试。
- 业务状态调整：无
- 业务流程调整：无
- 接口契约调整：无
- 数据模型或迁移：无
- 高风险设计：无

## 影响与验证

- 影响范围：现有折扣计算分支及调用它的金额展示，不改变金额计算规则。
- 回归验证：修复前新增用例应失败，修复后 10.05 × 0.9 得到 9.05。
- 回归验证：整数金额、零折扣和既有金额计算测试保持通过。
- 现场待验证：测试人员在原报错版本对应的场景中核对金额展示。
