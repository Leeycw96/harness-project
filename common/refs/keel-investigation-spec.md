# 问题调查（S）

## 问题定位

- 共同工作要求遵守 `.codex/common/refs/keel-work-spec.md#通用工作要求`。

- 可查看相关代码、配置、已有测试和已提供的日志，运行授权检查。定位时不修改业务代码、测试、配置或数据，不加日志代码、不提交；需要改代码取证时先说明需求。

- 按已确认的要求判断对错，记录代码版本、日志来源和现场条件。本地复现有帮助，但不是必要条件；发现代码缺陷时仍要说明它为什么能解释本次现象。

错误示例：代码里有日志语句，就断定本次运行经过该分支；没有日志，就断定事件未发生。

- 结论使用“已定位、候选原因、暂未定位”。已定位要有能解释现象的证据；不确定时列出查过什么、支持和反对证据，以及还不能确定什么，不猜测补全。

- 多个候选原因分别给出区分方法。请求日志时说清关键字或代码位置、时间范围或请求标识、必要字段和用途。只索取必要信息；拿不到证据就如实说明，不能写成已排除。

- 无法复现原场景时，说明哪些代码行为可以验证、哪些仍需现场核对。回归测试通过、诊断日志补齐、原 BUG 已消失分别记录，不能互相代替。
