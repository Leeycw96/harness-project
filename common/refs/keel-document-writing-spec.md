# 文档表达规范（S）

## 文档表达

- 文档使用短句和短段落，每个条目只有一个要点；现有章节内的结论、变化或要做的事位于前面。
- 业务行为用日常说法，少用术语和缩写；必要术语首次出现有简短解释，字段、状态、接口和符号准确。
- 内容限于本次任务需要的变化、影响和结果，无长篇背景、工作流水账或无关设计。
- 同一信息只有一份，其他位置引用；图表已表达的内容不重复，报告不复制整份计划。
- 结果直接写短结论，无需附代码片段、执行记录、日志存档或引用；场景规范要求的 SQL、PlantUML 和接口示例完整。
- 精简不省略必需章节、字段、关键条件或未验证事项；篇幅按任务需要，不设统一字数上限。

错误示例：通过幂等语义构建回调链路的闭环协同能力。

正确示例：同一退款回调重复到达，只处理一次，不重复发送通知。
