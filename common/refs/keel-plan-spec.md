# Keel Plan Spec（S）

## 工作与资料边界

- 根据项目手册识别实际语言、架构、数据库和验证工具。模板中的 Java/PostgreSQL 仅为示例，替换为项目事实，不强制类、Service、Maven 或指定数据库。
- 业务流程资料用于定位入口与生命周期，须核对代码、模型、配置及测试。索引缺失、过期或冲突时以实际实现为依据，区分现状与目标，不虚构已有能力。
- 只可写任务指定的计划索引、功能文档和审阅素材；不改业务代码、测试、配置或流程索引，不创建提交，不手写 HTML。规范允许的操作仍受本次任务范围和用户授权限制。
- 已核实事实、假设和待决事项分开说明，记录证据。必要选型依据官方或一手资料，说明选项和权衡；已确认决策沿用，最终交付不能留关键业务或技术选择给实现者。

## 从简与本期范围

- 按本期功能目标组织计划，不把每个步骤或文件拆成独立功能；小调整可只包含一个功能文档。
- 变化点详述，沿用部分简述。时序图可把连续未改动步骤合成“沿用订单查询与归属校验”等业务块，说明对应实现依据，不能只写含糊的“其他逻辑不变”。
- 保留理解改动所需的入口、关键参与方、前置条件、重要分支、事务边界、异步和失败补偿。新增状态影响异常/重试时，这些分支仍需展开。未选时序图时也要有必要执行说明，不能标“不涉及”来省略实现逻辑。
- 数据模型、接口确实无变更时，MD 保留章节并使用下文的本期不涉及标记；HTML 省略无变更的可选栏目，业务流程采用本次共用粒度规范，有流程变化时总览必需，无变化可省略。无关旧状态和调用细节不必展开，但变化的入边、出边及条件必须清楚。
- 新增状态不一定新增字段，但可能改变数据库枚举/约束、SQL、接口响应枚举、校验和状态筛选；须逐项核实，不能以“无新增接口/字段”代替无变更判断。只列变化字段，不重新描述完整旧接口或表结构。
- 引用本次其他功能的模型或接口表示本期依赖该设计，保留明确引用及必要说明，不能同时标注本期不涉及。代码改造点列全必要联动，不加入无需修改的文件凑数。

## 产物约定

`.keel/plans/<name>.md` 为功能索引，`<name>.features/<slug>.md` 为按需读取的执行设计；`<name>.review.md` 仅补充背景、当前流程和状态机。HTML 从这些源文件生成，目标、验收、模型、时序图、接口和改造点只维护一份，不独立编造另一套审阅方案。

审阅素材在一级标题后、背景前记录 `- 业务流程变化：有` 或 `无`，以及 `- 判定依据：…`，说明按共用粒度对比的阶段/路径及证据。这两项供检查，不作为 HTML 栏目。无法判定时先补充证据，不能填无。旧素材未记录判定时，只兼容保留完整总览图的形式。

## Markdown 执行计划

索引只保留 `## 功能目标`，每项用 `### slug — 功能名`。记录 `- 文档：[slug](<name>.features/<slug>.md)`、`- 依赖：无` 或先行功能 slug（多个用 `、`），然后写 `- 目标：…` 和 `验收标准：` 下的逐项列表。目标和验收只描述技术上要实现的功能效果，不写 HTTP 路径、字段、状态码、事务机制或实现步骤。依赖必须对应已定义功能且不能成环。

每个功能 MD 以 `# slug — 功能名` 开头，与索引一致，只包含以下四章，不重复背景、目标和验收：

- **数据模型**：用一条 `- 结构变更：新增表`、`新增字段` 或 `其他调整` 记录类型，多种用 `、` 分隔；无自身调整写 `- 结构变更：无`，且无本期共享模型引用时另写 `本期不涉及数据模型变更，沿用现有实现。`。新增表/字段必须有 PlantUML ER 图；明确字段、约束及 `sql` 围栏。仅索引、既有字段调整或回填也写 SQL，但不触发 HTML 模型章节。按项目方言及迁移约定写 SQL，必要的执行顺序和恢复要求就近说明。
- **功能时序图**：用 `- 时序图：生成` / `不生成` 记录已确认选择。选中时用 PlantUML 描述详细逻辑，图旁可简述实现约定；未选时保留必要执行说明，不强制画图。这类文字只在 MD，HTML 只汇总已选图的功能。
- **接口设计**：单独维护本功能所需的 HTTP/RPC 请求、响应和错误契约，格式同 HTML 要求；无变更写 `本期不涉及接口变更，沿用现有实现。`（旧文档的 `本功能无接口变更。` 仍兼容）。不在时序图旁复制整份字段契约。
- **代码改造点**：直接列文件、类/方法或函数，每项仅一句话说明改什么；核实既有符号，标明新增，不重复功能分类。不得塞入 SQL、验收清单或详细步骤；Builder 根据目标、模型、时序图和接口设计完成必要联动修改。

共享模型或接口只在一个所属功能定义，其他功能在对应章节写 `- 引用：[owner-slug](owner-slug.md#数据模型)` 或 `#接口设计`，直接指向定义，不链式引用、不复制 SQL 或重复接口契约。引用功能无自身模型变更时记“无”；迁移由所属功能执行，索引声明必要的先行依赖。读取索引后仅加载当前功能及明确引用章节，依赖关系不要求加载整份依赖文档。

不另生成汇总大 MD；不新增背景、状态机、技术约束、实施顺序或验证方案章节。索引及关联功能文件须可独立校验和完整快照，Builder/QA 无需读取 HTML 或审阅素材。

## HTML 审阅稿

只按以下八类内容排列，条件章节无内容时省略，不填“无变化/不适用”，不增加“其他必要说明”：

1. **背景**：仅用 `- User Story：作为…，我希望…，以便…` 列表表达理解后的用户诉求。不添加功能分类标题、slug、目标或验收标准，不要求 Story 与功能一一对应。目标和验收标准放下一独立栏目。
2. **功能目标**：独立展示技术上需要达到的功能效果及逐项验收结果，直接复用索引；不展示 HTTP 契约、事务处理等实现细节，审阅素材不重复编写。
3. **业务流程总览**：按共用粒度有业务流程变化时必需；无变化可省略，用户明确要求时也可展示。用 PlantUML 活动图表达当前业务触发、主要阶段、关键分支和结果，参考流程索引并核对代码；不将技术入口数量当业务节点数，不把目标流程混入现状。全新业务说明当前缺少该流程，展示实际相关上下游，不虚构已有能力。
4. **状态机**：仅状态或流转条件调整时写入审阅素材，保留目标流转与本期变化；目标状态效果放 MD 功能目标，具体执行规则放时序图或执行说明。
5. **数据模型设计**：仅新增表或字段时从 MD 数据模型生成。ER 图展示本次相关表、必要关联表、主键/关联键和变化字段，标记新增/修改，说明必要类型及约束。未改的几十个字段可省略；表达关联基数，区分逻辑关系与实际外键，不虚构约束。
6. **功能时序图**：复用 MD 中已选重点功能的图，隐藏选择记录。
7. **接口设计**：仅 HTTP/RPC 有变化时从各功能 MD 汇总，按接口本身组织，不展示功能编号、slug、功能名称或目标说明。HTTP 三级标题写成 ``### POST `/path` ``，RPC 写成 ``### RPC `Service.method(Request)` ``。字段表包含类型、必填及简短说明；少量变化只写差异。请求/响应示例标明局部，删除字段不进入新示例，无请求体/响应体则直说，不虚构 JSON。
8. **代码改造点**：直接复用 MD 的文件定位和一句话说明。

## 图表与交付标准

- 图用自包含 `plantuml` 围栏，每块一组 `@startuml` / `@enduml`，不生成独立图源文件；禁用外部 include、文件读取与远程资源。ER 使用 `entity`，流程总览使用活动图。
- 时序图表达重点功能的入口、关键参与方、调用次序、重要分支、事务边界、异步交互及状态变化，与目标、模型和改造点一致。
- 状态图以新流转为主体，新增绿色 `#DCFCE7` + `[新增]`、修改蓝色 `#DBEAFE` + `[修改]`、删除红色 `#FEE2E2` + `[删除]`。删除节点放独立“本期删除”区域，不接入目标流转；变化边也标注，实际状态变化符号在 MD 中可定位。
- 检查所有功能都有目标、逐项验收、代码改造映射，已选时序图完整；ER 字段与 SQL 一致，接口与状态契约在功能 MD 中无遗漏，共享引用可达且无重复定义。关键假设须核实或获用户接受，不留未决标记或关键选型。
- 图像嵌入 HTML 后可离线审阅，不能用图表源码代替实际渲染结果。源文档、图表、SQL 和生成的 HTML 必须一致。
