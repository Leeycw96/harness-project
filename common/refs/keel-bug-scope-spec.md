# 局部修复边界（S）

## 分类结论

- “局部修复”结论仅适用于根因明确、已有确认要求且不改既定设计的实现缺陷；缺陷标签或改动行数不是资格依据，尚未明确的分类为待判断。

- 改变预期、新增需求，或调整业务状态/流转、业务流程、接口契约、数据模型/迁移，以及需专项设计的权限、事务并发或跨模块改动，分类为需要方案设计。内部条件或计算修正不一定改变流程；流程索引中的状态、流转或执行符号变化仍属设计影响。

正确示例：复用已有舍入规则修正折扣金额，可按局部缺陷处理。

## 修复资格

- 预期依据、分流结论位于同目录 `investigation.md` 的 `## 修复资格`，不重复到简要修复说明；固定字段如下：

- 预期依据：已确认要求及出处。
- 分流依据：为什么适合局部修复或需要设计。
- 定位结论：已定位、候选原因、暂未定位之一。
- 事项分类：缺陷、需求变更、待判断之一。
- 处理路径：fix、plan、待判断之一。
- 业务状态调整：无、有、待确认之一。
- 业务流程调整：无、有、待确认之一。
- 接口契约调整：无、有、待确认之一。
- 数据模型或迁移：无、有、待确认之一。
- 高风险设计：无、有、待确认之一。

- 有效局部修复声明为“已定位、缺陷、fix”且五项边界均“无”，符合已确认业务约定。无需为资格字段附加代码、日志或复现存档；调查进展位于其他章节。

- 批准产物包括首次确认时复制的修复说明 `approved.md` 与调查说明 `approved-investigation.md`，作为本次执行输入；不要求文档哈希、资格摘要或后续内容一致性校验。

## 验收记录

- 实现和验收结果对应已确认的 `approved.md`、`approved-investigation.md`，质量结果符合 `.codex/common/refs/keel-code-quality-spec.md#代码与测试标准`。

- 代码验收与原场景复验分别说明，报告简述已验证行为、关联回归与现场缺口；超出局部修复范围的结果不能记通过，说明影响与所需设计。
