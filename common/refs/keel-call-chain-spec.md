# Keel CallChain Spec（S）

## 操作约束

项目手册及本次提供的专项规范补充语言、架构、目录和验证命令。发现规范冲突或必要资料缺失时报告，不自行放宽约束。

- 流程维护：只可修改指定索引目录中的相关文档并提交这些文档；不修改业务代码、测试或已有实现提交。
- 保留用户无关改动；只 stage 本次授权文件，不自动 merge、squash、push 或清理已有提交。
- 不读取与任务无关的历史运行资料。规范允许的操作仍受本次任务范围和用户授权限制。

## 业务流程索引

索引目录默认为 `.keel/call-chain/`。一个 `<domain>-<flow>.md` 对应一个业务流程，不按接口、业务域或 feature slug 建文件。

### 维护范围

变更包含外部 HTTP/RPC/MQ/Scheduler/callback 入口新增、删除或语义变化，异步推进点变化，或业务状态节点、流转条件、生命周期、状态变更符号变化时，才评估更新。

命中已有流程时更新其文件。没有文件时，只有同一业务目标由两个及以上外部入口推进、初始请求后仍有异步推进，或业务对象存在跨阶段生命周期状态流转，才新建。

不涉及业务状态机的查询、统计、导出、单步 CRUD、内部调用、DAO、DTO、参数校验不维护；不能仅因变更位于内部模块就忽略状态变化。默认不更新，无法确认时说明证据缺口，不推测创建索引。

### 文档标准

每份流程文档包含：

- 一句话业务目标。
- 入口目录：步骤、触发类型、仓库相对路径、入口符号、说明。
- 从开始到终态的业务步骤。
- 当前业务状态机：状态名称/值、含义、初态/终态及自包含 PlantUML 状态图；无状态机则说明不适用。
- 状态流转表：源状态 → 目标状态、触发事件、前置条件、业务入口符号、实际执行状态变化的符号及证据路径。异步流转标明 MQ/Scheduler/callback 等触发；创建、失败、重试、补偿和终态按代码记录。

新增或修改状态、边时同步图表；删除时清理当前状态与关联边，历史差异留给 git，不保留计划中的删除节点或本期高亮。入口与状态变更执行符号分别定位，无类语言直接记录模块与函数，不虚构类名。

不记录普通内部同步调用、DAO、DTO、查询或单步 CRUD，不扩展为完整调用栈；实际执行状态变化的内部符号是必要例外。
