# Keel CallChain Spec（S）

## 操作约束

项目手册及本次规范补充技术栈、目录和验证命令；冲突或资料缺失须报告，不放宽约束。

- 只修改并提交指定索引目录内的相关文档，不修改业务代码、测试或已有实现提交。
- 保留用户无关改动，只 stage 本次授权文件；不自动 merge、squash、push 或清理提交。
- 不读无关历史资料；允许的操作仍受任务范围和用户授权限制。

## 业务流程索引

目录默认为 `.keel/call-chain/`。按共用粒度分组，每个 `<domain>-<flow>.md` 对应一个流程。

### 维护范围

外部 HTTP/RPC/MQ/Scheduler/callback 入口增删或语义、异步推进点、业务状态节点、流转条件、生命周期或状态变更符号变化时评估更新。

命中已有流程则更新；没有文档时，仅同一目标由两个及以上外部入口推进、初始请求后仍有异步推进或存在跨阶段生命周期状态流转，才新建。

不涉及业务状态机的查询、统计、导出、单步 CRUD、内部调用、DAO、DTO、参数校验不维护；内部模块的状态变化仍须检查。默认不更新，不确定时记录证据缺口，不推测创建索引。

### 文档标准

每份文档包含业务目标、从开始到终态的业务步骤，以及：

- 入口目录：步骤、触发类型、仓库相对路径、入口符号、说明。
- 当前业务状态机：名称/值、含义、初态/终态、自包含 PlantUML 状态图；无状态机说明不适用。
- 状态流转表：源/目标状态、触发事件、前置条件、业务入口符号、实际执行状态变化的符号及证据路径；标明 MQ/Scheduler/callback 等异步触发，按代码覆盖创建、失败、重试、补偿和终态。

增改状态/边同步图表，删除时清理节点和关联边；历史差异留给 git，不保留计划删除节点或本期高亮。入口和状态执行符号分别定位，无类语言直接记模块/函数，不虚构类名。普通内部调用栈不展开，实际状态变更位置必须保留。

## 维护结果

报告给出 NOOP 或 UPDATED、检查的提交范围、入口与状态变化证据、已有文档与新建条件的判断，以及更新文件、文档提交或未更新原因。更新内容以实际代码为准；不确定时说明证据缺口，不能把计划中的目标当作已实现行为。
