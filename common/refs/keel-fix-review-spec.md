# 修复说明编写规范（S）

## 修复说明

### 说明结构

简要描述：一级标题为 BUG 标识与短名称，仅写以下五章；内容简短易懂，示例替换为项目事实。

1. **问题**：现象与预期结果。
2. **原因**：用短句解释根因。
3. **改造点**：遵守 `.codex/common/refs/keel-code-change-spec.md#改造点`。
4. **影响点**：受影响的业务流程或能力。
5. **建议验证点**：建议回归的业务流程与关键结果，必要时标明原场景待复验。

### 展示从简

简要描述：改造点用列表，其余用短段落，不展开证据代码、行号、内部判定、测试用例/文件或步骤。HTML 只展示这五项，不重复完整源文档；保留 Markdown 下载。

### 旧说明兼容

简要描述：新说明用五章；旧三章（问题与根因、修复方案、影响与验证）仍可读取，重渲染只展示五项简述。既有已批准 HTML 不自动重渲染，原 Markdown 下载保留原文。
