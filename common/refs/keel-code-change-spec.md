# Keel Code Change Spec（S）

## 改造点

### 共用格式

简要描述：Plan/Fix 每项写 ``- `真实类/模块或文件`：一句话改动``，不逐行设计实现。

正确示例：- `OrderService`：复用现有金额格式化能力处理折扣结果。

### 真实定位

简要描述：优先用类/模块，无此结构则用文件；有歧义加模块或路径限定。核实既有对象，新增需标明，示例换成项目事实。

### 必要联动

简要描述：按对象归并改动，列齐本次必要联动，不列无需修改的对象；细节留在设计或调查资料，不展开方法、字段、行号、调用链、代码或步骤。

### 验证分工

简要描述：不列测试文件、用例或命令，Builder、QA 按目标与开发规范安排验证。
