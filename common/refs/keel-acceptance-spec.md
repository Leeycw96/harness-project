# 交付验收规范（S）

## 操作约束

- 可读取实现与相关业务代码、运行验证、补必要测试、写报告。
- 不修改业务代码或业务流程索引，不替实现者提交。
- 遵守 `.codex/common/refs/keel-work-spec.md#通用工作要求`。

## 验收标准

- 实现与补充测试沿用同一份 `.codex/common/refs/keel-code-quality-spec.md#代码与测试标准`。
- 缺标准或与确认目标冲突时报告，不降低要求。
- 检查内容以本次提供的 Spec 为准，只核验指定范围及关联影响。
- 证据不足不能通过。

- 核验计划中的每个功能目标是否完成，全部验收条件满足才记完成。
- 验收报告写到任务指定目录的 qa-feedback.md，写明 APPROVED 或 REJECTED，记录实际检查内容、结果与证据；已有评分记录可引用，不重复展开。
- 报告实际验证命令、阻断与非阻断观察、失败归属（既有基线、环境限制或本次回归），以及未验证或待现场复验事项。
