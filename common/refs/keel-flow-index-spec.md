# 业务流程文档维护规范（S）

## 操作约束

- 遵守 `.codex/common/refs/keel-work-spec.md#通用工作要求`。
- 只改并提交指定索引目录的相关文档；不改业务代码、测试或既有实现提交。

## 业务流程索引

- 默认目录 `.keel/call-chain/`；按共用粒度，每流程一份 `<domain>-<flow>.md`。

- 外部 HTTP/RPC/MQ/Scheduler/callback 入口增删/语义、异步推进点、业务状态节点、流转条件、生命周期、状态变更符号变化须评估更新。
- 已有流程更新；无文档且同一目标由至少两个外部入口推进、初始请求后异步推进、跨阶段生命周期状态流转任一成立才新建。
- 查询、统计、导出、单步 CRUD、内部调用、DAO、DTO、参数校验无业务状态机则不维护；内部模块状态变化仍查。默认不更新；不确定记证据缺口，不推测新建。

- 含业务目标、开始至终态的业务步骤及：

- 入口目录：步骤、触发类型、仓库相对路径、入口符号、说明。
- 当前业务状态机：名称/值、含义、初/终态、自包含 PlantUML 状态图；无则写不适用。
- 状态流转表：源/目标状态、触发事件、前置条件、业务入口符号、实际状态变更符号、证据路径；标明异步触发，依代码覆盖创建、失败、重试、补偿、终态。

- 增改状态/边同步图表；删除时清理节点及关联边。历史差异留 git，不留计划删除节点/本期高亮。分别定位入口/状态执行符号，无类语言用模块/函数，不造类名。普通内部调用栈不展开，实际状态变更位置必留。

## 维护结果

- 报告含 NOOP/UPDATED、检查提交范围、入口/状态变化证据、已有文档/新建条件判断、更新文件及文档提交或未更新原因。以实际代码为准，不把计划目标当已实现；不确定记证据缺口。
