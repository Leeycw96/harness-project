# 业务流程文档维护规范（S）

## 业务流程索引

- 默认目录 `.keel/call-chain/`；按共用粒度，每流程一份 `<actor>-<action>.md`，以参与者及其业务动作命名，如 `user-order.md`（用户下单），不以库存占用等内部资源操作代替流程主题。

- 文档反映实际实现，只记录主流程、业务状态和业务入口的变化，不把未实现的计划写成现状。
- 已有流程文档按实际变化维护；新增文档仅适用于同一目标由至少两个外部入口推进、初始请求后异步推进、跨阶段生命周期状态流转任一成立的流程。
- 无业务状态机的查询、统计、导出、单步 CRUD、内部调用、DAO、DTO、参数校验不属于索引范围；内部模块的业务状态变化仍属范围。范围不确定时说明未确认事项，不能声明无需维护或凭猜测新增文档。

正文只含以下三部分：

1. **主流程说明**：从用户或客户调用 API 的业务目标出发，用编号步骤简述触发至结果，如用户下单 → 库存扣减 → 下单完成；取消、失败等业务分支并入相关步骤。后台任务、MQ、Job 按其推进的业务目标归属，不单独展开内部调用。
2. **状态机**：用简短文本箭头描述真实状态及分支，转移旁注明对应主流程步骤编号或业务动作，如 `INIT --步骤 1：提交订单--> PENDING`。状态与步骤尽量对应，不为凑步骤编造状态；无业务状态机写不适用。状态、流转与主流程一致，删除失效描述。
3. **业务入口**：只列触发类型（HTTP、RPC、MQ、定时任务、回调等）、入口名称（如 HTTP 方法与路径、RPC 方法、MQ 主题或 Job 名）、业务实现符号及必要的仓库相对路径。定位业务 Handler、消费者、Job 或模块函数；不列框架配置、注册器、通用 Dispatcher 等框架层入口。

保持简短；不附 PlantUML、详细流转表、实际状态写入符号、SQL/锁、参数、日志、测试或内部调用栈等实现细节。

## 维护结果

- call-chain-review.md 简述 NOOP/UPDATED、检查范围、已有文档/新建条件判断、更新文件或未更新原因，无需附代码片段或验证存档；结论符合实际实现，未实现的计划目标不属于现状，不确定项有简要说明。
