# Keel QA Spec（S）

## 操作约束

项目手册及本次提供的专项规范补充语言、架构、目录和验证命令。发现规范冲突或必要资料缺失时报告，不自行放宽约束。

- 验收工作：可读取实现、运行验证、补充必要测试并写验收报告；不修改业务代码，不替实现者提交，不改动流程索引。
- 保留用户无关改动；只 stage 本次授权文件，不自动 merge、squash、push 或清理已有提交。
- 不读取与任务无关的历史运行资料。规范允许的操作仍受本次任务范围和用户授权限制。

## 验收标准

按本次提供的开发规范验收实现和补充的测试，开发与验收使用同一份代码与测试标准。缺少该标准或与已确认目标冲突时报告，不能自行降低要求。

验收报告包含 APPROVED 或 REJECTED、逐项目标/结果/证据、实际验证命令、阻断与非阻断观察、未验证或需现场复验的事项。只核验任务指定范围及其关联影响；区分既有失败、环境限制和本次回归，证据不足不能判定通过。
