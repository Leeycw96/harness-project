# Skill 与 Agent 两段输入协议

日期：2026-10-10

用户已确认采用“任务＋Spec”，修改归入 4.0.3。

## 业务输入

- 任务说明本步目标、范围、必要资料引用与交付要求，可以引用已确认的计划或修复快照。
- Spec 列出当前场景规范的 name 与绝对路径，可限定二级章节。
- 角色配置和项目环境由调用层提供；不转发整份 Skill、历史对话、task_ref 或运行字段。

## 职责与记录

Agent 自主完成任务，返回业务结论、产物、commits、验证证据和遗留项。QA 的 APPROVED/REJECTED、流程维护的 NOOP/UPDATED 保持为业务结论。

主会话持有运行状态、当前原生执行标识、阶段、登记产物、完成标记和恢复计数；根据原生新消息调用现有记录助手。产物、提交及证据核对后才记录完成，再推进状态。现有脚本没有自动消息采集器，不新增独立 dispatcher。

仅当前执行的新进展可重置检查时间；轮询、重复摘要和 running 状态不算新进展。无进展时间到达时先检查，确认失联后结束旧执行并创建新任务，旧结果不能用于新执行。

## 保留的边界

保留确认与快照检查、三轮返修、每阶段每角色两次恢复、产物定向补做一次、五/十五分钟检查点及旧 profile/shadow 恢复。Fix 派发前及记录完成前均复核批准版本，代码验收通过仍仅等待原场景复验。

新绑定只记录 agent、spec_refs；旧 task_ref 可保留在历史状态中，但不再下发或使用。职责规范直接选择场景来源，问题调查不继承代码实施权限。

## 验证

临时部署检查两段输入、直接场景引用和实际权限；覆盖主会话记录、缺产物阻断、旧完成日志不推进状态、批准变化阻断及计数保留。固定输入统计角色配置和实际 Spec，动态任务与真实模型执行成本另行评估。
