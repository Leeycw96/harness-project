# QA 做事风格与评分设计

日期：2026-10-11

用户已明确：检查内容由人直接修改 Spec，Skill 稳定编排 Agent 和 Spec；不做检查开关、章节选择、自动减检或高分策略。

## 风格与规约

换到别的项目仍应采用的核实、判断和沟通方式，属于 Agent 做事风格；具体权限、质量标准、报告格式和评分内容，属于项目规约。

QA 保留先核实再判断、围绕任务范围工作、按事实与约定判断、区分新旧问题、讲清依据五种风格，不固化项目必检清单。四份 Agent 的“原则”改称“做事风格”，保留 TDD、最小修改、核实现状等专业方法。

Spec 删除重复的通用做事方法；实现要求写成可核验的标准，不命令 QA 修改业务代码或替实现者提交。通用质量要求保持一个来源，继续整份下发；以后从 Spec 删除一条检查，不需要修改 Skill，也不由 Agent 的旧清单补回。

## 评分记录

新增评分 Spec，约定业务结果 JSON 和评分工具。JSON 记录当前规范要求的实际检查，不设置固定质量检查种类；Python 按每组实际检查条目计算通过比例，不决定验收是否通过。

当前目标完成检查按 Plan 的功能目标等权计分：已验证完成目标数 ÷ 全部确认目标数 × 100。feature slug 作为目标 ID，一个功能的验收条件全部通过才算完成；失败、遗漏、未验证不算完成。分母从任务提供的计划快照读取，不能自行少列目标得满分。

其他检查按实际条目记录名称、passed/failed/unverified、简短原因和证据引用。评分内容可以随 Spec 增删，未检查的内容不补成通过或 100 分；没有目标检查结果时不计算目标分。

首次结果保存在本次报告目录的 qa-score.json，不允许不同内容覆盖；复验使用独立记录，不能用复验子集满分替换首次成绩。记录保留当次结论、阻断项、目标清单和证据摘要，旧任务无记录显示未评分。

Fix 按批准的代码修复作为一个目标，得 0 或 100 分，现场复验事项另行保留。Dev 和 Fix、初验和复验分开展示。

## Python 工具

common/scripts/keel-qa-score.py 提供 record 和 history，部署到 .codex/common/scripts/。record 接收业务结果 JSON、计划或修复说明与报告目录；history 查看最近成绩、完成数、失败和未验证项，可筛选 Builder，并输出 JSON。

工具只计算、保存和查看评分。不读取或修改 state、phase、返修计数、运行进度，不调用运行助手，不决定下一次检查内容。验收结论取自 QA，不从分数推断 APPROVED。

评分工具属于 QA 报告生成工具。Skill 只向 QA 提供本轮业务资料和 Spec，接收其结论与产物；保持既有推进、批准、返修和现场复验流程，不增加 Markdown 文风检查。

## 验证与同步

验证目标分母、未验证不加分、通用检查增删、空检查不满分、首次成绩不覆盖、复验独立、历史过滤、旧任务无记录和临时部署。同步 README、规范目录与 4.0.3 分支日志，保留精简门禁。
