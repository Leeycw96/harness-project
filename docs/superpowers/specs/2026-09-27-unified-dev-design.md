# 统一开发编排入口

## 目标与边界

只保留 keel-dev 开发入口，合并原 fast 的小范围实现方式。A 与 S 不变：复用 Builder、QA、CallChain 和对应规范；O 按任务依赖决定一次实现或分片，QA 通过后按实际改动决定 CallChain 是否需要参与。keel-fix 的独立缺陷闭环不变。

## 执行

已确认 Plan → Preflight → BUILD → REVIEW。QA 阻断进入 FIX/REVIEW_FIX，最多三轮；通过后检查本轮 Builder diff。明确无入口、异步推进、状态/流转或状态执行符号变化则记录 noop 并结束；有变化或不确定则调用 CallChain 独立判断。不能用改动大小或是否有业务总览图代替检查。

新任务使用同一初始化函数、阶段和完成标记；保留既有 mode=full 存储值以兼容状态消费者。删除 fast Skill 和专属初始化函数、阶段任务说明及当前文档中的入口推荐。部署仅清理 manifest 跟踪的废弃文件。

## 恢复

resume_keel_run 校验未完成任务的计划快照，将旧 fast 阶段映射到统一阶段并补齐 CallChain 状态；保留提交、QA 报告、Preflight、计数、规范绑定与进度，不重建 run。重复恢复不重复迁移，旧 profile 的进度路径仍可用。已完成任务保持原样；输入不是开发任务或快照不合法时拒绝且不改历史。

旧执行须先结束，主会话核对已有完成标记、产物与提交后续作，补齐缺失职责绑定；不能因升级重置修复上限或重复实现。后续新反馈仍按原规则新建任务，方案变化返回 Plan。

## 验证

在临时目录验证统一初始化、按需跳过/运行/shadow、阶段标签、旧 fast 各阶段和 profile 恢复、历史数据不变与重复恢复；升级部署移除旧 Skill 但保留用户文件。验证 Plan 快照与 Fix 独立闭环不受影响。既有 Agent 定义与 TOML 不改，不以静态契约测试代替真实模型端到端评估。
