# Keel Plan 4.0 审阅与执行内容设计

## 已确认内容

HTML 按背景、功能目标、业务流程总览、状态机、数据模型设计、功能时序图、接口设计、代码改造点排列。流程总览必选，使用 PlantUML，参考 CallChain 并核对代码，展示当前业务关键环节而非方法调用。背景仅展示理解后的 User Story 列表，不含功能分类标题或 slug；功能目标为独立栏目，直接复用 MD 中的目标与逐项验收列表。状态机仅在调整时出现。新增表或字段时展示 ER 图，只列相关表、关系和关键字段。时序图按用户选择生成。接口仅在 HTTP/RPC 变化时出现，以 HTTP 方法与路径或 RPC 签名作为标题，不展示功能编号、功能名称或目标说明。不保留其他说明、技术约束、实施顺序或验证方案独立章节。

执行内容改为轻量索引和按功能拆分的 MD。索引保留功能目标、验收列表、文件链接和先行依赖；技术目标只描述效果，不混入 HTTP 契约或实现机制。每份功能 MD 固定包含数据模型、功能时序图、接口设计、代码改造点。模型写本次 SQL 与相关 ER，时序图写重点功能详细逻辑，接口独立列请求/响应/错误，改造点只列文件与符号并一句话描述改动。无模型或接口变化明确标记；未选时序图时保留必要执行说明。

## 产物与一致性

`.keel/plans/<name>.md` 为索引，`<name>.features/<slug>.md` 为功能文档，`<name>.review.md` 仅保存背景、当前业务流程与按需状态机。同名 HTML 从这些源文件汇总生成，沿用已确认的八类栏目与展示规则。接口设计直接复用功能文档，HTML 中不展示所属功能分类。下载提供 ZIP，包含原始索引和全部功能文件且保持相对链接；不生成另一份汇总 MD。

共享模型与接口仅在一个功能定义，其他功能直接引用所属文件的对应章节。SQL 迁移由所属功能执行，不重复复制；有先行要求时写入索引依赖。依赖必须有效且无环，引用必须直接指向实际定义，禁止链式引用和重复接口定义。功能文档标题与索引 slug/名称一致，文件路径限制为计划目录下的相对路径，不使用符号链接。

Dev 初始化校验完整文档集合，在 run 中快照索引为 `plan.md` 并保留功能目录结构，`state.plan_path` 指向此索引；无需审阅素材。Builder 先读轻量索引，只加载指定功能及必要共享章节，不一次展开全量文件或依赖全文。QA 逐功能完成验收，修复阶段只读相关功能和受影响依赖；CallChain 按实际 diff 读取相关设计。运行恢复始终使用快照，不引用会变化的源计划。

背景 Story 不要求与功能一一对应。新增表/字段要求 ER 图，数据库变化要求 SQL。缺少功能文件、当前流程、关键契约、存在未决标记或图表渲染失败时拒绝生成并保留旧 HTML。用户反馈修改对应源文件后重新生成同名 HTML，最终审阅通过再进入 Dev。

## 阅读主题

HTML 顶部提供深色/浅色切换，默认沿用深色，在浏览器可用时记住上次选择。主题同时覆盖背景、正文、导航、表格、代码及审阅状态；图表保留原有底色和状态语义颜色。存储不可用时仍可切换，打印固定使用浅色。切换脚本内嵌以支持离线使用，由渲染器计算 CSP 哈希，仅允许该脚本执行；文档内容仍按原规则转义。

## 落实顺序与验证

1. 修改 Markdown 校验及 HTML 组合渲染，保留本地 PlantUML、安全转义和成功后原子替换。
2. 更新执行模板，增加审阅素材模板，更新 Plan Skill 和 HTML 文案。
3. 对齐 Builder、QA、Dev 和共享输入说明；删除对旧独立章节的依赖。
4. 验证分文件覆盖、引用与依赖、接口单一来源、ZIP 文件集合、可选章节及图表、损坏输入保留旧 HTML、full/fast 快照与源文件隔离。
5. 在临时目标验证部署和已部署渲染入口，执行仓库契约检查并检查最终差异。

实现保留当前分支及已有版本修改，不部署到本仓库或其他长期项目。已有历史设计文档保持历史内容。
