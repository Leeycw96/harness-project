# QA 通过时精简交付

用户要求 QA 通过时少写验收内容，允许省略 `qa-feedback.md`；修改归入 4.0.5。

## 交付与衔接

- APPROVED 默认只返回简短通过结论、当次评分 JSON 路径及必要的非阻断观察或现场缺口；可省略验收报告，生成时也只写简短概要。
- REJECTED 保留 `qa-feedback.md`，简述阻断项、原因、影响与返修所需信息。
- 评分 JSON 和验收标准沿用；初验与复验分别保存，评分不代替验收结论。
- Dev/Fix 依据当前 QA 返回结果推进。通过且无报告时，以返回的当次评分 JSON 登记完成；未通过时仍登记报告。已有报告不被当作本次验收结果，Fix 代码验收与现场复验仍分别说明。
- 现有阶段助手支持评分文件作为产物，运行状态中的报告路径保留兼容用途，无需新增脚本或主会话复查。

## 验证

覆盖 Dev/Fix 无报告通过、复验使用当次评分、未通过且缺报告阻断和缺产物保护；运行现有 runtime 与指令精简契约，在临时目录验证部署。
