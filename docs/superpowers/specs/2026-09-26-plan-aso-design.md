# Plan 的 ASO 与从简设计

## 已确认目标

先在 README 固化项目 ASO 设计规范，再将 Plan 拆为 Planner 角色、Plan Spec 与 keel-plan 编排。方案按本期差异表达，变化讲清楚，未改动内容简要带过；原目标、产物结构、HTML 同源生成和最终用户确认保持不变。

## 职责

- A：新增 keel-planner，Markdown 仅有角色、能力、原则。包括从简设计、最小改动、先看已有实现、变化点讲清楚、沿用部分简述、不漏关键影响及实事求是。仅新增其注册 TOML，不修改既有 Agent TOML。
- S：keel-plan-spec.md 承接原 Plan 的文档与图表标准，并规定图中合并未变步骤和本期不涉及标记的使用条件。Spec 只规定操作边界及交付要求，不调度角色或管理阶段。
- O：keel-plan 组织原生 Planner 调研、用户决策与时序图选择、起草/修订；主会话检查完整性与简洁程度，渲染 HTML 并取得最终确认。主会话不重复调研或编写方案，Planner 不直接询问用户、渲染 HTML 或推进流程。

角色、规范、任务章节与输出范围按次显式提供，可独立替换但须符合交付接口；缺资料或冲突须报告。调研只读，起草仅写指定源文档，不修改业务代码、测试、配置或流程索引，不增加开发 run 初始化与进度协议。

## 产物与兼容

仍为轻量索引、每功能四章 MD、审阅素材与同名 HTML，不新增面向执行的计划文件或 HTML 栏目。Planner 与 CallChain 通过编排读取同一份业务流程粒度规范；按业务阶段和路径判定总览，有变化必需、无变化可省略，用户明确要求时也可展示。总览表达当前业务；状态图和时序图保留本次变化及必要前后文。事务、异常、补偿或超时受到影响时必须展开，不能用“其他逻辑不变”隐藏设计。

无模型变更时保留结构变更为无，正文写“本期不涉及数据模型变更，沿用现有实现。”；无接口变更写“本期不涉及接口变更，沿用现有实现。”，兼容旧的无接口变更表述。HTML 不展示无变更的可选栏目，下载与快照保留 MD 的明确标记。

标记不能与本期实际模型/接口变更、SQL 或共享设计引用混用。新增状态引起接口枚举或数据库约束调整仍属于本期变化，必须据实设计，不能因无新增字段或接口而省略。

## 共用流程粒度

业务目标界定流程，业务阶段或决策界定节点；HTTP/RPC、MQ、定时任务与回调仅是技术触发点。共用规范不改变 CallChain 的维护门禁：业务阶段未变也可能需要更新入口、状态流转及实际变更代码位置。规范由 O 注入，不绑定在角色定义中。

审阅素材一级标题后记录业务流程变化（有/无）及非空判定依据；有变化时缺总览图拒绝渲染。旧素材没有判定字段但保留总览时继续兼容。仅补内部状态的增量示例省略总览，保留状态和选中时序图；无任何图的方案不要求 PlantUML。

## 验证

新增内部校验状态的示例保留未改动生成/校验规则，明确状态衔接和原超时扫描的必要联动；无模型和接口变更的 MD 标记在 HTML 中隐藏。验证新旧标记兼容、矛盾标记拒绝、下载与快照一致及真实 PlantUML 渲染。

在临时项目测试 plan/dev 部署包含 Planner 注册和角色、Plan Spec 与引用资源，扩展 ASO 边界检查。保留现有 Dev/Fix 契约和体量门禁，报告完整 Plan 指令体量，不将内容搬出 Skill 作为节省结论。静态/部署/渲染检查不等同真实 Planner 模型任务评估。
