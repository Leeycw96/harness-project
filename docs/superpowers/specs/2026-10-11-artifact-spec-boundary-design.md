# Spec 与做事风格的边界

## 目标

管理者给任务和产物要求，Agent 自主完成工作。Spec 只对产出物生效，不规定 Agent 的工作步骤、工具或操作权限。

## 归属

- 任务：本次目标、范围与授权、必要资料和交付要求。
- Spec：代码、文档、图表、验收报告和评分 JSON 的内容、格式及质量。
- Agent 做事风格：证据判断、实现方法、只读调查、独立验收、改动保护和授权意识。
- Skill：选择 Agent 与 Spec、用户沟通、阶段交接、进度及恢复。

错误示例：Spec 要求先读代码、运行测试，再写报告。

正确示例：报告包含结论、实际验证结果和证据。Agent 自主选择如何获得这些结果。

文档栏目顺序和代码的业务行为仍是产物要求，不属于 Agent 的执行步骤。

## 调整范围

逐份改写现有 Spec，将行为要求移回四个 Agent 的做事风格。通用工作 Spec 改为通用交付标准，删除五个旧角色分类入口；名称及章节引用直接更新，不保留 Spec 兼容接口。

Skill 仍只传“任务＋Spec”。QA 的检查内容由用户直接修改产物规范，评分规范只定义结果，不强制生成方法，不增加检查开关、自动减检或文档检查流程。

## 验证

核对产物与行为要求的归属，验证规范元数据、当前引用、临时部署清理和已有运行门禁；执行计划、修复及评分契约测试，维持原输入体量门槛。
