# Markdown 产物表达规范设计

日期：2026-10-10

用户已确认：只给 Agent 输入文档表达 Spec，不增加产物检查。

## 检查结论

Plan 和 Fix 说明已有局部从简要求，验收报告、调查记录、返修单和流程维护报告缺少共用表达标准。现有 QA 样本逐项证据较长，流程报告重复解释范围与维护依据，可以保留结论和证据引用、减少复述。

plan.md 是 Planner 方案的执行快照；Builder 按任务返回实现与验证结果，不要求额外创建报告。本次约束 Agent 实际写出的 Markdown，不增加产物或改写历史快照。

## 方案选择

新增共享文档表达 Spec，直接加入各阶段 Agent 的 Spec 输入。规则保持一个来源，不增加主会话复审、自查步骤或字数门禁。

## 文档表达

规范名为 keel-document-writing-spec，description 说明它用于计划、调查、修复说明、实现记录、验收和流程等 Markdown 产物。

- 用短句和短段落，每个条目说明一个要点；在现有章节内先说结论、变化或要做的事。
- 用日常说法讲业务行为，不堆术语和缩写；必要术语首次出现时简短解释，实际字段、状态、接口和符号保持准确。
- 只写本次任务需要的变化、影响、结果和证据，不写长篇背景、工作流水账或无关设计。
- 同一信息只写一次，其他位置引用；已在图表说清的内容不再复述，不复制整份计划。
- 证据写短结论和可定位的引用，保留必要命令、结果和关键片段，不大段粘贴调查日志或已有实现代码。场景规范要求的 SQL、PlantUML 和接口示例仍须完整。
- 精简不省略必需章节、字段、关键条件、验证证据或未验证事项；篇幅按任务需要，不设统一字数上限。

错误示例：通过幂等语义构建回调链路的闭环协同能力。

正确示例：同一退款回调重复到达，只处理一次，不重复发送通知。

同步规范目录、README、4.0.3 分支日志和已有部署契约清单；验证新规范在各默认输入中可达、名称唯一、部署一致以及精简门禁，不增加文风检测器。
